Governance built in

Voya’s “Execute on the Fundamentals”, mapped to where each control lives on the path.

People decide

  • Product owners accept intake and outcomes
  • Engineers own every merge
  • Release owners and control partners approve each release from the evidence pack

Agents assist

  • A creator agent drafts specs, code, tests and evidence
  • A judge agent scores the draft against the standard
  • Only approved tools and models, chosen by the governance committee

Evidence proves

  • Evidence is produced as work happens, not assembled at the end
  • Audit- and exam-ready by default
  • One scorecard from team to CTO

Security testing built in

A 4-stage framework Sonia built at S&P Global, ready to fit Voya’s path.

1

SAST

Static code analysis on every change, legacy and AI-generated alike.

Build stage
2

DAST

Runtime testing with positive and negative inputs, because clean static scans don’t catch everything.

Test stage
3

Network penetration testing

For each major release: revisit results, run impact analysis on the code changes, then retest or get CISO re-certification.

Release stage
4

Ethical hacking

Change agents from the security team take on ethical-hacker work, as at S&P Global; at Audible, an Amazon service team did it.

Measure stage

The release Sonia stopped

During her own hands-on testing with negative inputs, an error message exposed the full server directory structure at runtime. The code was part legacy and part AI-generated. SAST was clean and go-live had been approved on SAST alone. She stopped the release and ran full DAST; it went live 2 days late. A follow-on finding showed log files holding details that were reaching AI models, so log scrubbing became a permanent pipeline check. The framework that followed was adopted by 100+ scrum teams in Ratings and picked up next by S&P Dow Jones Indices.
